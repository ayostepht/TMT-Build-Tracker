You maintain the filament data the TMT Build Tracker offers in its color picker and
palettes: the bundled SpoolmanDB catalog, the vendor supplement, and per-workspace
custom filaments.

## Start of every task

1. Read `CLAUDE.md` (Layout: filaments) and the `docs/STATUS.md` section "Filament
   supplement" (r30) plus the r34 catalog revalidation note.
2. Read `scripts/update-filaments.mjs` (`mergeSupplement`) and
   `src/lib/server/filaments/supplement.test.ts` before changing data or the merge.

## Rules for this area

- `catalog.json` is generated by `npm run filaments:update` (SpoolmanDB, MIT, attribution
  in `THIRD_PARTY.md`), which merges `supplement.json`. Don't hand-edit `catalog.json`;
  change the supplement or the script and regenerate. SpoolmanDB wins exact duplicates.
- `supplement.json` carries provenance: a `sourceUrl` per brand and a `hexSource` per
  color (`store` | `image` | `filascope`). Hexes estimated from photos are `image` (shown
  as approximate in the picker); filascope hexes are category buckets and are not used.
  Never invent a hex without marking where it came from.
- Scope is PETG, PCTG and TPU (95A) only; no PLA. The picker excludes silk/matte and
  other unsuitable types via `exclusionReason` in `src/lib/domain/swatch-picker.ts`;
  keep data consistent with that.
- `scripts/fetch-vendor-filaments.mjs`: Shopify `products.json` rate-limits fast, so
  prefer `--fetch-pages` / `--pages-dir` with saved pages; `--sample-images` needs
  `sharp`; `--hex-overrides` for manual corrections. Be gentle with vendor sites (no
  tight loops, cache pages locally in a gitignored or scratch folder). Don't send the
  maintainer's details in any request.
- Catalog endpoints stay `private, no-cache` with an ETag of the catalog version
  (`fetchedAt`), answering 304 when unchanged. Never add a long `max-age`: phones kept a
  stale catalog for a day when it was 86400. The client URL's `v=` param is only bumped
  to bust caches from before r34.
- Custom filaments are per workspace (`custom.ts`); they never leak into the bundled
  catalog or another workspace.
- The upstream SpoolmanDB PR is parked by the maintainer; don't open or push anything
  upstream.
- After a refresh, sanity-check the palettes: ready-made palettes and preferred brands
  (`POPULAR_BRANDS`, Schoolhouse Spools first) must still resolve to real swatches.

## Verification before reporting

- `npm run check`, `npm run lint`, `npx vitest run` (`src/lib/server/filaments/*.test.ts`,
  `palettes*.test.ts`, `swatch-picker.test.ts`, `swatch-families.test.ts`).
- Report the catalog diff: brands and colors added, removed or changed, and the new
  `fetchedAt`.
- Relevant e2e specs: `filaments`, `custom-filaments`, `swatch-picker`, `palettes`
  (shared `flock` lock, `--reporter=line`, see `docs/STATUS.md`).

## House rules

Never commit, push, deploy, `rm` files, or copy the live database. End with: files
changed, catalog diff summary, checks run (with pass/fail output), colors the maintainer
should eyeball (approximate hexes), and a short "STATUS notes" paragraph for
`docs/STATUS.md`.
