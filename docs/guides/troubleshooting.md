# Troubleshooting

Start with the container log: `docker logs tmt-build-tracker` (on Unraid also the container's **Logs** menu). Lines from the app begin with `[tmt]`.

| Symptom                                                                                | Cause and fix                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Container stops at start, log says `unable to open database file`                      | The data folder is not writable by the container user. Quick start: `sudo chown 1000:1000 data`. Unraid: `chown 99:100 /mnt/user/appdata/tmt-build-tracker`. Then start again.                                                                                                                                                                                                                                                               |
| Container stops with `Refusing to start: configuration problems`                       | The lines after it in the log list each problem: `BETTER_AUTH_SECRET must be set` (the variable is empty; `openssl rand -hex 32`), secret too short, too few distinct characters or "looks like a placeholder", an invalid `TMT_MODE`/`SIGNUP`/`XFF_DEPTH`, a half-configured Google/GitHub pair, or missing public-mode requirements such as an https `PUBLIC_URL`, `ADDRESS_HEADER` or `ADMIN_EMAILS`. Fix them and start again.           |
| Sign-in says "too many requests", or people get locked out of signing in               | Behind a reverse proxy without `ADDRESS_HEADER`, every user shares the proxy's address and therefore one sign-in limit (3 per 10 s). The log shows a one-time warning "A reverse proxy appears to be in front of this server". Set `ADDRESS_HEADER=x-forwarded-for` (and `XFF_DEPTH` if more than one proxy is in front), but only if every request reaches the app through the proxy; keep the container port off the internet and the LAN. |
| Pull fails with `unauthorized` / `denied`                                              | The package is private. See [Image access](../../README.md#image-access).                                                                                                                                                                                                                                                                                                                                                                    |
| Sign-in or any form fails with "Cross-site POST form submissions are forbidden" or 403 | You opened the app through an address that does not match `PUBLIC_URL` (the LAN IP while `PUBLIC_URL` is the https domain, or the reverse). Use the `PUBLIC_URL` address, or empty `PUBLIC_URL` to allow the plain IP. With a proxy and `PUBLIC_URL` empty, make sure the proxy sends `Host` and `X-Forwarded-Proto`.                                                                                                                        |
| Uploads (STEP zip, 3MF, photos) fail with 413 or a stalled upload through the proxy    | The proxy limits body size. Add `client_max_body_size 1100m;` (NPM, Advanced) or the equivalent for your proxy, see [Reverse proxy](reverse-proxy.md). The app itself accepts 3MF files up to 1024 MB (`MAX_3MF_MB`, `BODY_SIZE_LIMIT=1100M`) and STEP zips up to 200 MB.                                                                                                                                                                    |
| Uploads fail with 507                                                                  | `MIN_FREE_DISK_MB` is set and the data volume has less free space than that. Free up disk space (or lower the value).                                                                                                                                                                                                                                                                                                                        |
| Changes from other people appear only after a reload                                   | The proxy buffers the live-update stream. Add `proxy_buffering off;` and a long `proxy_read_timeout` (see [Reverse proxy](reverse-proxy.md)); on other proxies disable response buffering for `/api/builds/*/events`.                                                                                                                                                                                                                        |
| Printer shows offline or "find printers" finds nothing                                 | The container must reach the printer's IP on your LAN. Bridge mode does; broadcast discovery needs host or `br0` networking (see [Printers](printers.md#docker-networking)). Check the printer's IP, access code and that LAN mode is on (Bambu).                                                                                                                                                                                            |
| The standard kit's 3D model or print files are missing                                 | Check the log for `[tmt] kit pack:` lines. The pack is inside the image and installs a few seconds after start; a failure is logged as `[tmt] kit pack: ...` and retried at the next start. If it needs a download (`KITPACK_URL`), the container needs internet access and `KITPACK_DOWNLOAD` must not be `off`.                                                                                                                            |
| SSO button missing                                                                     | One of `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` is empty.                                                                                                                                                                                                                                                                                                                                                                       |
| SSO button shows but sign-in fails                                                     | `PUBLIC_URL` is not set to the https address, the redirect URI at the provider is not `<PUBLIC_URL>/api/auth/callback/oidc`, or the container cannot reach the issuer's address from inside Docker. See [Single sign-on](sso.md).                                                                                                                                                                                                            |
| Printer access codes ask to be entered again                                           | `BETTER_AUTH_SECRET` changed. Re-enter them.                                                                                                                                                                                                                                                                                                                                                                                                 |
| Everyone was signed out after an update                                                | `BETTER_AUTH_SECRET` is different from before (for example a new random value in a recreated container). Use the original value.                                                                                                                                                                                                                                                                                                             |
| Someone forgot their password                                                          | The app sends no email. Create a one-time reset link on the server: [Backup and upgrade](backup-and-upgrade.md#forgotten-passwords).                                                                                                                                                                                                                                                                                                         |
| The app does not offer an offline page or "new version" prompt on a phone              | Those need an https address (or `localhost`); on plain `http://<server-ip>` the app works as a normal web page. See [Install on your phone](phone-install.md).                                                                                                                                                                                                                                                                               |
