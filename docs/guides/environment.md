# Environment reference

Every setting is an environment variable on the container (`-e`, `--env-file`, the `environment:` block of Compose, or a Variable in the Unraid template). Empty optional variables behave as if unset. The image already sets `NODE_ENV=production`, `BODY_SIZE_LIMIT=1100M`, `PORT=3000`, `HOST=0.0.0.0`, `DATABASE_URL=/data/tmt.db` and `KITPACK_DIR=/app/kitpacks`.

`docker-compose.example.yml` and `.env.example` list the same variables as commented examples.

## Required

| Variable             | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET` | The app refuses to start (exits with a message) when it is missing, shorter than 32 characters (after trimming), has fewer than 10 distinct characters, or looks like an obvious placeholder such as `changeme` (the check catches obvious placeholders, not every weak value). Only `NODE_ENV=development` or `test` skips the check, and an unset `NODE_ENV` counts as production. Generate with `openssl rand -hex 32`. Also derives the key that encrypts printer access codes: changing it makes them unreadable and signs everyone out. |

## Address and proxy

| Variable                         | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `PUBLIC_URL`                     | Optional public URL (no trailing slash). Unset: the request's own address is used (http unless a proxy sends `X-Forwarded-Proto: https`) and cookies are never `Secure`. Set: that origin is forced for every request, cookies are `Secure` and SSO redirect URIs are built from it. `BETTER_AUTH_URL` and `ORIGIN` still work as older names. See [Reverse proxy](reverse-proxy.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ADDRESS_HEADER`, `XFF_DEPTH`    | The header that carries the client address (for example `X-Forwarded-For`) and how many proxies to skip from the right of that chain (default 1, digits only). They decide the client address used for sign-in rate limits (3 attempts per 10 s per address) and by adapter-node. Set `ADDRESS_HEADER=x-forwarded-for` when the app sits behind a reverse proxy, and `XFF_DEPTH` if more than one proxy is in front, but ONLY when ALL traffic reaches the app through proxies you control that overwrite the header (for any header other than `X-Forwarded-For` the value is used verbatim; a client that can reach the port directly could pick any address). When unset, a client-sent `X-Forwarded-For` is ignored and the socket address is used: behind a proxy that means everyone shares the proxy's address and one sign-in limit, and the log shows a one-time warning about it. When set but the header is missing (or `XFF_DEPTH` exceeds the chain), sign-in requests are refused with 400 and a line is logged. |
| `PROTOCOL_HEADER`, `HOST_HEADER` | adapter-node settings. `scripts/proxy-origin.mjs` sets them to `x-forwarded-proto` and `x-forwarded-host` if you did not, and rewrites those two headers on every request. Leave them alone.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `PORT`, `HOST`                   | Listen port and address. Default `3000` and `0.0.0.0` in the image (the health check follows `PORT`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

## Accounts and sign-in

| Variable                                                                               | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ADMIN_EMAILS`                                                                         | Optional comma-separated emails that are site admins (kit and 3D model management), besides the first user. Case-insensitive; read at start.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `SIGNUP`                                                                               | `open` (default), `invite` or `closed`: who may create an email/password or SSO account on a self-hosted install. `invite` needs an invitation link addressed to the person's email; `closed` accepts nobody new. Both still allow the very first account on an empty database. Does not apply in `public` mode. Recommended `invite` or `closed` for any install reachable from the internet and whenever OIDC is used: with `open`, someone can register an address before its real owner and block that person's SSO login.                                                                                                                                                                                                                                     |
| `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`                                  | Optional OpenID Connect login (for example Authentik). All three enable the SSO button. The app uses `<OIDC_ISSUER>/.well-known/openid-configuration` to find the endpoints. Redirect URI to register: `<PUBLIC_URL>/api/auth/callback/oidc`. See [Single sign-on](sso.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `OIDC_PROVIDER_NAME`                                                                   | Label for the SSO button ("Sign in with NAME"). Default `SSO`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | Google / GitHub sign-in, used in public mode. A provider is on only when both of its variables are set; one without the other fails at start. Register the redirect URIs `<PUBLIC_URL>/api/auth/callback/google` and `<PUBLIC_URL>/api/auth/callback/github`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `TMT_MODE`                                                                             | `selfhost` (default) or `public` (SSO-only hosted instance). Public mode: sign-in only with Google and GitHub (no passwords, no generic `OIDC_*`, which is refused), emails must be verified by the provider, printers reached through an OctoEverywhere link and printers that are not connected are allowed, and local printer addresses, printer discovery, custom camera addresses and Spoolman are not available (see [Printers](printers.md#hosted-or-self-hosted)). It refuses to start unless `PUBLIC_URL` is an https origin on a real host name (no credentials, path, localhost or IP address), at least one of Google/GitHub is configured, `ADDRESS_HEADER` is set (trusted proxy) and `ADMIN_EMAILS` lists an admin. Any other value fails at start. |

There is no email verification and no password reset email: the app sends no email at all. See [Backup and upgrade](backup-and-upgrade.md#forgotten-passwords) for reset links.

## Storage and kit pack

| Variable                                         | Description                                                                                                                                                                                                                                         |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                                   | SQLite file path. Default `/data/tmt.db` in production, `./data/tmt.db` in dev. Uploads and the installed kit pack live in an `uploads` folder next to it.                                                                                          |
| `KITPACK_DIR`, `KITPACK_URL`, `KITPACK_DOWNLOAD` | Kit pack location (default `/app/kitpacks` in the image), download URL pattern (`{slug}` `{version}` `{file}`) and `KITPACK_DOWNLOAD=off` to never download (the pack inside the image is used regardless). See [docs/kit-pack.md](../kit-pack.md). |
| `MIN_FREE_DISK_MB`                               | Free space to keep on the data volume; upload routes answer 507 below it. Whole number of MB or `off`. Default `0` (off) self-hosted, `2048` in public mode. Validated at start.                                                                    |

## Upload and body limits

| Variable          | Description                                                                                                                                                                                                                                                                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BODY_SIZE_LIMIT` | Largest request body adapter-node accepts. The image sets `1100M` (above `MAX_3MF_MB`, so sliced projects fit). adapter-node's own default is 512 kB, so if you run the app another way, set it. It applies to every route. Must stay at least `MAX_3MF_MB` plus 1 MB; the server logs a warning at start if not.                       |
| `MAX_3MF_MB`      | Largest 3MF in MB the Files tab and the kit drop zone accept (default `1024`, `256` when `TMT_MODE=public`; a project sliced with G-code for every plate is several hundred MB). It is streamed to disk, parsed (only the small `Metadata/` entries are read, never the G-code) and deleted. Needs `BODY_SIZE_LIMIT` at least as large. |

On top of `BODY_SIZE_LIMIT` the app caps each route on its own: 1 MB for JSON and form posts, 9 MB for photos, 3 MB for guide pages, 2 MB for snapshots and imports, 200 MB for STEP zips and `MAX_3MF_MB` plus 1 MB for 3MF files, answered with 413 even for chunked bodies. Uploads are sent as the raw file body (not multipart), so the server streams them to disk instead of holding hundreds of MB in memory. A reverse proxy needs `client_max_body_size 1100m;` (Nginx) or the equivalent, see [Reverse proxy](reverse-proxy.md).

Default `120` per minute with burst `60` in public mode; off self-hosted unless `WRITE_RATE_PER_MIN` is set (burst then defaults to half of it). Over the limit: 429 `{error, code: "rate"}` with `Retry-After`. Counted in memory per process.                                                                                                                                                                                                                        |

## Printers and advanced

| Variable               | Description                                                                                                                                                                       |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TMT_PRINTERS`         | `off` disables the background printer status connections (default on). See [Printers](printers.md).                                                                               |
| `TMT_ARRANGE_OPTIMIZE` | `off` makes the plate arranger use only its basic packer. A diagnostic switch for bug reports; leave unset.                                                                       |
| `TMT_GCODE_BUDGET_MS`  | Time budget in milliseconds for reading per-object statistics from the G-code of one uploaded 3MF (all its plates together). Default `240000` (4 minutes). Rarely needs changing. |
| `NODE_ENV`             | Set to `production` by the image. Only `development` or `test` relax the secret check; never set those on a real install.                                                         |

Printers: a printer or Spoolman host must be on a private address (10.x, 172.16-31.x, 192.168.x, 100.64-127.x, loopback or IPv6 local); the only public destination is an OctoEverywhere shared link. Camera streams that redirect are not followed. In public mode only OctoEverywhere-link printers and not-connected printers are available; local addresses, discovery, custom camera addresses and Spoolman are not. See [Printers](printers.md).
