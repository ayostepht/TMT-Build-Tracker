## Map

- `src/lib/server/db/`: `app.schema.ts` (app tables), `auth.schema.ts` (generated by the
  Better Auth CLI; regenerate, don't hand-edit), `schema.ts` re-exports both.
- `src/lib/server/auth.ts`, `src/lib/permissions.ts`: auth setup and team roles
  (owner / editor / viewer via organization access control).
- `src/lib/server/startup.ts`: migrate + seed on server start (`init` hook).
- `src/lib/server/seed/`: template seed data (`types.ts` is the contract, `tmt.ts` the
  MakeGood kit, `index.ts` the list); see its README.
- `src/lib/domain/`: pure, framework-free logic (no DB, Svelte or Node imports).
  `types.ts` is the shared contract (`BuildView`, `PartState`, `PrintRun`, `PartPatch`;
  change it deliberately, it binds server, domain and UI). `accounting.ts`, `actions.ts`,
  `now.ts`, `grouping.ts`, `format.ts`; `fixtures.ts` builds a test `BuildView` from the seed.
- `src/lib/server/access.ts`: `ApiError`, `requireMember/Editor/Owner`, `buildAccess`
  (non-member → 404, viewer write → 403).
- `src/lib/server/builds/`: `view.ts` (`loadBuildView`), `create.ts` (`createBuild`
  snapshots the design), `actions.ts` (every mutation goes through `mutateBuild`).
- `src/lib/server/events.ts`: in-process pub/sub per build (single container; SSE at
  `/api/builds/[id]/events`). `src/lib/server/teams.ts`: chapter helpers (writes go
  through Better Auth `auth.api`).
- `src/lib/client/`: `api.ts` (typed fetch helpers that throw the server's message),
  `live.ts` (`subscribeBuild` EventSource with reconnect), `printer-store.svelte.ts`.
- `src/lib/components/`: UI; `build-context.svelte.ts` holds the live view and `act()`
  (mutate, then re-fetch the view).
- `src/lib/server/compress.ts`: gzip for html/json responses (wired in `hooks.server.ts`)
  and cached gzip for GLB downloads.
- `src/routes/(app)/`: signed-in area (layout guard → `/login`; `/` → active workspace):
  `builds/[id]/` tabs, `teams/[slug]`, `onboarding`, `studio`, `designs`, `admin`.
  `src/routes/invite/[id]` sits outside the group. `src/routes/api/`: JSON endpoints;
  `/api/health` for the Docker healthcheck.
- `drizzle/`: committed SQL migrations. `.github/workflows/docker.yml`: CI (check, lint,
  unit, e2e, route-folder gitignore guard) and the multi-arch image to GHCR.
- `e2e/`: Playwright specs, `fixtures.ts`, `helpers.ts`.

## Build state (`build-state`)

- `domain/guards.ts`: the one `isObj` / `Obj` plain-object guard; server, printer, kit pack
  and Spoolman modules import it instead of defining their own.
- **Mutations:** `mutateBuild` (users) / `mutateBuildSystem` (printer-driven) in
  `src/lib/server/builds/actions.ts`: access check → domain function → patches + `activity`
  row in one transaction → SSE emit. State rules live in `src/lib/domain/actions.ts` and
  return `PartPatch[]`.
- **Run history is the source of truth** for run-driven statuses: `recompute.ts`
  (`recomputeParts`) replays a part's runs through `applyRun`; `deleteRun`/`updateRun`
  recompute targeted parts (`?recompute=0` to skip). Undo right after logging:
  `POST /api/builds/[id]/runs/[runId]/undo` with a client snapshot.
- **Live printer jobs win over run history:** `applyRun`/`recomputeParts` take
  `opts.livePrinting` (slugs on a `printing`/`paused` printer job of the build, from
  `livePrintingSlugs(tx, buildId)` in `builds/actions.ts`). A Failed/Partial run, a run
  delete/edit, or an undo leaves such a Printing part untouched (a retry is on the bed);
  Success still prints it. `printingAction` 'start' takes `startedAt` from the build's active
  linked job (clamped to now) and the estimate from the printer's `last_status`
  (`elapsedSec + remainingSec`), via `startPrinting(view, slugs, now, live)`.
- **Variants:** `templates.variant_groups`, `builds.variant_choices`, `domain/variants.ts`.
  `BuildView.parts`/`state`/`plates` hold active parts only; `allParts` has everything.
- **Workspaces:** every user has a personal workspace (organization with metadata
  `{ personal: true, userId }`, "My builds", created on sign-up and lazily for legacy users
  in `teams.ts`). Personal workspaces can't take invitations. Builds move personal → chapter
  via `POST /api/builds/[id]/move`.
- **Drafts (Studio):** a `builds` row with `kind = 'draft'`. Hidden from
  `buildRows`/`recentBuilds` (default `kind = 'build'`), team page, Builds menu and printer
  job matching (`findPlateForFile`, `linkJob`, `expect`); `draftRows` lists them.
  `mutateBuild`/`mutateBuildSystem` refuse any activity kind outside `draftAllows` with 400;
  `setSetupStep` and `phase` edits are refused too. UI: Design, Files, Settings tabs only
  (others redirect to Design); Settings shows a printer/layout summary linking to Files.
  Editors can delete drafts. `POST /api/builds/[id]/promote` sets `kind = 'build'`,
  `setup_step = 5`, writes `build.promote`, and opens the wizard at Export.
- **Log a whole plate:** `LogPlateButton` opens `LogRunSheet` with `quick` (Success,
  finished now, time = started→now if Printing else the plate's per-run time, grams =
  slicer/learned grams per run). Sheet shows "Print 1 of 2" on multi-run plates.
- **Pace** (`domain/pace.ts`): sum(actual)/sum(plate time) over successful timed
  whole-plate runs; ignores failed/partial, subset runs, hours <30% or >300% of plate time,
  and hours exactly equal to the plate time (an unedited prefill). Needs 12 estimated hours.
  Each run is compared with the time it printed against (`print_runs.est_seconds`).
  `PlateTime.svelte` shows "≈ 9.4 h at your pace · slicer 10 h"; Now printing's ETA uses
  the pace when no printer job reports its own.
- **Run choice on per-part plates** (`domain/run-choice.ts`): perPartRuns plates (rims,
  plate 13) print one part per physical print. Default (`defaultRunParts`): the part
  already Printing, else the first part not Printed with runs left; never all.
- **Filament by role** (`domain/accounting.ts`): a sliced file's grams per role
  (`Plate.filamentGrams`) go through `plateFileRoleGrams(plate, partRoles)`, which keeps
  only roles that a part on the plate has (a file's slot → role map can disagree with the
  design: stray TPU slots on PETG plates). `roleShares`/`filamentStats` use the kept grams
  renormalized; `estPerRun` stays slicer grams, else the file's full total, else BOM / runs;
  no overlap → the parts' own roles. `splitGramsByRole` (`spool-split.ts`, Spoolman
  deduction) uses the same helper for whole-plate runs.
- **Part print logs:** `partRuns(view, slug)` in `logrun.ts` includes whole-plate runs
  that cover the part; `RunTable` tags them "Plate N · whole plate".
- **Activity:** every activity kind needs a sentence in `describeActivity` /
  `describeActivitySegments` (`domain/activity.ts`); payload text is control-char stripped
  so it can't forge links. `ActivityList` links to `/print#plate-N` / `#part-<slug>`; the
  Print tab applies non-persisted overrides, scrolls and flashes 2 s.
- **Print tab toolbar:** stored per build in localStorage `tmt-ui:<id>` as
  `{ role, hide?, group }`, grouped by Plate by default (see Print toolbar below).
- **Quotas and caps** (`server/quota.ts`): every creation path calls `assertUnder(tx, key,
count, {userId})` in the same synchronous transaction as its insert; a refusal is a
  `QuotaError` (409, or 429 for slots) with `{error, code: 'quota'}`; `null` limit = no
  query; only site admins are exempt. Bytes are measured from files on disk
  (`workspaceUploadBytes`, `userUploadBytes`), never from client sizes; `assertUploadRoom`
  before writing, `enforceStreamedUpload` after streaming. Slots: `acquireSseSlot`,
  `acquireUploadSlot`. Constants in both modes: 2000 runs per build (`assertRunRoom`,
  `assertRunTotal`), activity pruned to the newest 5000 per build (`pruneActivity`).
- **Live streams** (`server/live-stream.ts`): shared SSE response; re-checks access on every
  event and, with session validity, on each 25 s heartbeat; releases its slot once.
- **Kit copies and builds**: `createBuild` refuses a copy owned by another workspace;
  `moveBuild` and deletions call `builds/repoint.ts` `repointBuildsOffTemplates` (other
  workspaces' builds go back to the copy's base kit).
- **Write rate** (`server/write-rate.ts`, called in `hooks.server.ts` after the session is
  resolved): token bucket per user on every non-GET request except `/api/auth/*`; off on
  self-hosted installs unless `WRITE_RATE_PER_MIN` is set; refusal shaped for the caller
  (action failure, HTML page, or JSON `{error, code: 'rate'}`).
- **Printer job linking**: a job links to a plate only by file name or by one bound
  expectation ("Start on <printer>", `jobId` in org settings, `ExpectedConfirm.svelte`);
  never guessed. `jobNeverStarted` (domain/actions.ts) releases a cancelled print without
  logging filament; progress is monotonic (`maxProgress`).

- **Start/log control**: `PlateControl.svelte` is the one control (Start printing / Finish &
  log / Take off printer / Log a print…) on Print, Files, the Now card and the landing;
  props `plate`, `only?`, `size?`, `alwaysLog?`. `PlateStart` and `LogPlateButton` are
  retired.
- **Optimistic actions**: `BuildCtx.act(fn, { patches })` applies `applyPatches`
  (`domain/actions.ts`) at once, rolls back on failure, and the re-fetched view always wins.
  `setPartStatus`, `startParts`, `takeOffParts`, `restoreParts` each push a 15 s Undo toast
  (`UNDO_MS`). Logging a run is not optimistic.
- **Print toolbar**: `PrintToolbar.svelte`; one row with a Filter sheet on phones, not
  sticky. Stored per build as `{ role, hide?, group }` in `tmt-ui:<id>`; "Hide printed"
  defaults on once a part is Printed; parts that become Printed during a visit stay visible
  ("Printed just now", `groupParts(..., { keep })`). Specs use `keepPrintedVisible`.

## Plates and 3MF (`plates-3mf`)

- **Implied bed for built-in layouts:** a build with no printer gets `view.layoutPrinter`
  from its MakeGood layout key (`layoutBed` in `src/lib/printers/layout-bed.ts`: `xpa` =
  Bambu X1 / P1 / A1 256 × 256, `h2d` = H2D / H2S 350 × 320, both 4 slots), derived in
  `loadBuildView` and never stored. The setup wizard, `PlatesPanel`, `ExportCard` and the
  export (`buildExportPlan`, `prepareExport`) fall back to it; arranging, re-arranging,
  printer jobs and uploaded 3MFs still need `view.printer`. A new tuned layout gets an
  implied bed by adding it to `LAYOUT_BEDS`.
- **Arranger:** `domain/arrange.ts` (see `arrange.README.md`). Flat rotations only
  (no 3D re-orientation code exists: removed 2026-11-11; `seed/arrange-tmt-snapshot.test.ts` pins the flat arranger's output); 1 mm default edge margin, 8 mm between parts, max
  clearance to edges and keep-outs; rigid source groups only when per-piece packing would
  split a part (wings, footrest, harness). "rotated N°" is shown on the part, never as a
  warning. Reference result: Elegoo Centauri Carbon 256 × 256 with the cutter keep-out, kit
  pack 1.0.1 → 21 plates, no warnings, export guard clean.
- **Layouts:** built-in `template_plate_layouts` (`xpa` default, `h2d`),
  `builds.plate_layout`. Named "MakeGood's Bambu ... profile" in the UI. Switching to a
  MakeGood profile while plates are arranged or uploaded asks first.
- **3MF parsing** (`src/lib/server/threemf/`): Bambu, Orca family, plain; reads `Metadata/*`
  only, never `3D/Objects/*`. Files on disk are read through the zip central directory
  (`zipfile.ts`); never fflate `Unzip` on a path. Elegoo 2.4 keeps plates in
  `model_settings.config` without instances, so objects come from `slice_info.config`
  (`identify_id`, `_id_N_copy_N` tail stripped); names use underscores (the matcher
  normalises). Limits: `maxThreeMfBytes()` (`MAX_3MF_MB`, default 1024), STEP zips 200 MB,
  `BODY_SIZE_LIMIT=1100M`. The browser sniffs big files with `File.slice` (`openBlobZip` in
  `client/kit-probe.ts`).
- **Matching and apply:** matcher `domain/plates-match.ts`; apply in `builds/plates.ts`
  (`applyUpload`). Plate-attached runs must be converted to per-part runs (`convertRuns`).
  Upload review offers "Use these plates" or "Use as print template" (default template when
  the build has a printer or arranged plates).
- **Twin parts** (`domain/twins.ts`): parts sharing a source file (rims `rims-1-4` accent,
  `rims-2-3` primary). An object mapped to a twin puts all active twins on the plate,
  `perPartRuns` true, runs = ceil(runsHint / twins) (warning when not divisible),
  `slicer_by_part` = plate grams per run per twin. "Use only <part>" overrides. Startup
  repair `repairTwinPlates` (`builds/twin-repair.ts`) fixes older uploads, idempotent.
- **Print template** (learned per-part data, `build_part_profiles`):
  `domain/part-profile.ts`, `builds/part-profiles.ts`. **exact** when G-code names objects
  (`domain/gcode-objects.ts`, run by `threemf/gcode-stats.ts`, 4 min budget), else
  **volume-split**. A part's grams count under its current role, so a recolor moves grams.
  Files tab "Print template" card; `DELETE /api/builds/[id]/print-template`. Not wired yet:
  "printer" and "manual" profile sources.
- **Plate time precedence:** manual (user) > slicer > learned > MakeGood profile > estimate
  (`domain/time-estimate.ts` splits MakeGood plate times by BOM grams; `estRough` for
  variant guesses). Manual times: `build_plates.manual_est_seconds` + `manual_est_source`
  ('user' | 'printer'), set in Files (`SlicerTimeInput`), from the Now card, or a printer
  job link (never over 'user'). `syncPlateTime` in `builds/actions.ts`. No time at all →
  dash and "no time estimate yet".
- **Files tab:** "Use my own sliced file" card (and drop anywhere) opens `PlateUpload` as a
  modal; the kit drop zone hands sliced projects to it (`BuildCtx.slicedFile`). With a
  printer set, `PlateLayoutPicker` shows a one-line `printerSummary()`. In build mode
  `PlatesPanel` owns the single `plates/layouts` fetch and hands it to the picker through
  `preload` (`null` = loading: heading seeded from the plates' `source`, select disabled).
- **Export:** `src/lib/server/threemf-export/` (Orca/Elegoo, Bambu, plain), painted
  supports, `bed_exclude_area`.

- Silhouettes are profile-only (`ensureSilhouettes` is the only lazy geometry fill; key
  `slug:piece`). Old footprint JSON and kit pack 1.0.1 still carry `orient` / `sil.poses`
  keys: readers ignore them (`domain/legacy-footprint.test.ts`). A stored arrangement with a
  legacy `pose` is stale and is re-arranged flat. `buildArrangement` (`builds/plates.ts`)
  also drops damaged stored items (null, non-object, no `slug`/`piece`, non-list `items`)
  and flags the arrangement `stale`; `buildExportPlan` throws a `PlanError`, never a
  TypeError; `time-model.ts` treats a non-array `items` as empty. The upload sheet routes
  Escape through the dialog's `cancel` event to `PlateUpload.close()`.
- **Uploads**: 3MF upload is a raw body only (`?name=`; multipart gets 415 before the body is
  read; curl uses `--data-binary`). Order on the plates route: upload slot (429), workspace
  already over (409), disk floor (507), stream. The raw 3MF is never kept; thumbnails under
  `3mf/<uploadId>/` and `plates/<buildId>/` count toward the workspace quota.
- **Zip safety**: files on disk are read through the central directory only
  (`threemf/zipfile.ts`; `cdSize` ≤ 64 MiB; no stream fallback: a missing directory is "not a
  valid 3MF"). The fflate push parser is for in-memory inputs and aborts past 64 MB of
  unwanted buffering. Bundles of 3MFs go through `print-geometry/nested-zip.ts` (entry
  count, per-entry, cumulative and declared-versus-actual caps; scratch folder removed in
  `finally`).

- The plate diagram is illustrative (`aria-hidden`); the legend's buttons are the
  accessible way to highlight and pin parts.
- **Files tab**: printed plates fold behind a toggle (`tmt-files-printed:<buildId>`), rows
  and cards carry `id="plate-N"` (hash opens a folded plate). One "Export format" select
  for the list (`client/export-flavor.svelte.ts`, per device) and a one-tap export per
  plate; `exportFilename` adds `-plateN` for any single-plate export, which `matchPlate`
  (`domain/printer-match.ts`) links by name.
- `learnPartProfiles` (`domain/part-profile.ts`) gives a plate's grams only to roles its
  parts have (stray slicer slots are skipped unless no slot matches).

## Printers and camera (`printers`)

- Read-only adapters (Elegoo SDCP, Moonraker, OctoPrint, Bambu LAN) in
  `src/lib/server/printers/`. The only write: Elegoo SDCP Cmd 386 `{"Enable":1}` via
  `sdcpEnvelope` (`adapters/sdcp.ts`, `SDCP_ALLOWED_COMMANDS = [386]`).
- **Camera:** `printers.camera_url` (override) + `camera_enabled`. Defaults at runtime
  (`camera-source.ts`): Elegoo `http://<host>:3031/video`; Moonraker
  `/server/webcams/list`; OctoPrint webcam settings; Bambu unsupported. Hub `camera.ts`
  (+ `mjpeg.ts`): one upstream per printer fanned out, latest frame kept, closed 30 s after
  the last viewer, 5 MB frame cap, 5 s connect / 15 s stall timeouts. Routes
  `GET /api/printers/:id/camera|/snapshot|/stream` (members, 404 otherwise),
  `POST /api/printers/camera-test` (editors). SSRF guard `checkCameraUrl`
  (`src/lib/printers/camera-url.ts`). Centauri Carbon answers `500 camera not ready` until
  Cmd 386: the enabler is sent before the first connect and on non-2xx/stall, throttled to
  once per 30 s per printer. UI: `CameraTile` on the Now printing card, collapsible
  (remembered as `tmt-camera-collapsed:<id>`, no requests while collapsed).
- **Jobs:** the supervisor emits a `job` event on job create/link/finish. Link/expect take
  optional `partSlugs` on per-part plates. Dismissing a job with no logged run releases its
  Printing parts (`printer.job.release`). Auto-link needs plate numbers in file names.
  Linking (`attach` → `linkPatches`): the job's start and estimate replace a part's Printing
  state unless another live job (`heldByOtherJobs`) covers the part; ended, unlogged jobs
  and manual starts never hold a part. A printer-sourced plate time follows; a typed one stays.
  Printer run-time numbers go through `sanePrintSeconds` (`domain/format.ts`: finite, >= 0,
  1 s to 30 days) before they become an estimate. `printers/status.ts` `unloggedEndedJobs` /
  `unloggedNotice` drive `UnloggedNotice.svelte`, a non-blocking notice shown when a plate has
  an ended, unlogged job: in `ExpectedConfirm` before linking, and after linking for every
  linked running job (`PrinterJobs`, Printers page), always derived from store jobs, never
  local state. `ConfirmPrintLog` exposes `#confirm-log-<jobId>` as its scroll target.
- **Client store** (`client/printer-store.svelte.ts`): sequence-guarded `load()`, refetch on
  SSE reopen / visibilitychange / online / focus, 30 s poll, "Printer status unavailable ·
  Retry".
- "Your printers" lists printers of every workspace the user is in
  (`GET /api/printers/mine?first=<org>`).
- **Elegoo via OctoEverywhere shared link** (`src/lib/printers/share-link.ts`): secret
  `shareLink` in `secretEnc` (normalised `https://shared-<token>.octoeverywhere.com`, never
  returned; only listed in `secretsSet`). With a link the adapter uses
  `wss://<link>/websocket`: no port, no UDP probe, MainboardID learnt from the first push,
  Cmd 1 once, no Cmd 0 polling, no Cmd 386 (`enableCamera`, `enableSdcpCamera`,
  `testEnabler` skip it). Camera `<link>/video` (MJPEG; no snapshot endpoint), guard pinned
  to the link host with https and the default port on every hop; a custom camera URL is
  cleared on save. `host` holds the placeholder `octoeverywhere`; without a usable link
  (e.g. secrets undecryptable) `guarded` in `adapters/index.ts` reports offline and nothing
  is dialled. `parseHost` rejects `*.octoeverywhere.com` and pasted links in Address.
  `safeError` masks share-link hosts. Live-probed read-only: the CC sends `PrintInfo.Status`
  20 while printing (OctoEverywhere shows it as "Bed Leveling", 0%).

- **r49 connections.** Options live in `src/lib/printers/connection-options.ts`
  (`GET /api/printers/options` returns `{ hosted, connectionOptions[] }`); setup text in
  `setup-steps.ts`; chooser grouping and labels in `integrations-view.ts`. Printers are
  added and edited only on the workspace Integrations page (`IntegrationPrinters`,
  `PrinterForm` with an `option`); `/teams/[slug]/printers` is the status view.
  `PrinterPublic.connection` is `lan | link | manual`. Shared links work for Elegoo,
  Klipper (https and wss to the link host, `/access/oneshot_token`) and OctoPrint (polled:
  10 s active, 30 s idle, through pinned requests); Bambu LAN cannot use a link. Kind
  `manual` (host placeholder `manual`) is never dialled; `expect` returns
  `{ manual: true, printer }`. In `TMT_MODE=public` the guard admits only a share-link
  host on calls with `allowShareLink` (https, default port, global-unicast answers);
  discovery, Spoolman, LAN addresses and custom camera URLs stay refused. Caps in the
  store transaction: link printers per workspace and per instance, manual per workspace
  (`config.ts`). Sockets (Klipper, Elegoo): 10 s handshake timeout, silence close (LAN 45 s
  / 20 s, link 120 s, `LINK_SILENT_CLOSE_MS`), `MessageBudget` (100 messages and 2 MiB per
  second, 1 MiB per message before parsing), `linkBackoff` for links. The runtime still
  buffers one message up to about 128 MiB (see STATUS). Test routes: `test-limit.ts`, 10
  per minute per user, uniform failures on a hosted site. Remote camera lists capped at 4.
  Tracking: `printing.start` carries an optional `printer` name in its activity payload;
  `startedOnPrinter` (`domain/activity.ts`) prefills the log sheet; `StartOnPrinter`
  links a running unlinked job at once; `betweenRuns` (`domain/actions.ts`) marks a part
  waiting for its next run.
- **Outbound guard** (`server/printers/outbound.ts`): every printer, camera, discovery and
  Spoolman connection goes through `assertOutboundAllowed` / `resolveAllowed` /
  `guardedFetch`: refused entirely in `TMT_MODE=public`; otherwise private ranges only, DNS
  resolved once and pinned, no redirects, metadata addresses denied. One exception: an
  OctoEverywhere shared-link host (`printers/share-link.ts` `isShareLinkHost`) is admitted
  when every DNS answer is a public address (`isGlobalUnicast`), https, no port. The exception
  is opt-in (`allowShareLink`, passed only by the link socket check, the link camera source
  and the two test routes in link mode); `maskSecrets` (`types.ts`) keeps the link host out
  of every `OutboundError`, `CameraError` and adapter message.
- **Shared link (Elegoo)**: encrypted secret `shareLink`, never returned; status over
  `wss://<link>/websocket` (address checked before each dial, not pinned), Cmd 1 once, no
  polling, no Cmd 386; camera `<link>/video` (pinned per hop). Host stored as the
  placeholder `octoeverywhere`, never dialled.
- **Remote data limits**: `MAX_REMOTE_MESSAGE_BYTES`, `safeFileName`/`safeText`,
  `HostileGuard` (long backoff after an oversize frame), MainboardID
  `[A-Za-z0-9_-]{1,64}`, 16 filaments; `mergeStatus` skips `__proto__`/`constructor`/
  `prototype`. Backoff resets only on a valid Status/Attributes frame; `linkBackoff`
  (10 s to 5 min) for links.
- **Secrets and destinations** (`store.ts` `secretsForDestination`): stored secrets belong
  to the address (host and port) or link they were saved for; changing the destination
  needs its own secret re-entered.

- **Client store** (`client/printer-store.svelte.ts`): one `OrgStream` (a single
  `EventSource`, the window listeners and the 30 s poll) per organization, reference
  counted and shared by every `PrinterStore` on the page; stores still load their own
  data. `CameraTile` takes a `name` for its labels; its enlarged view is a `ds-modal`
  dialog with a head and Close button. `PrinterCard`'s status pill is a `ds-badge` with a
  state-to-tone map.
- **Job linking UI**: `JobLinkControl` (core; never guesses a plate), used by `PrinterJobs`
  (build page) and `PrinterJobLink` (Printers page, build picker first). `GET
/api/printers?org=` returns `builds` and `expected` for editors only;
  `pendingExpected(db, org, buildId?)`. A disabled printer reads "Monitoring stopped";
  buttons "Stop monitoring" / "Resume monitoring".

## Design studio (`design-studio-ui`)

- **DesignWorkspace** (`components/build/DesignWorkspace.svelte`, also used by the wizard
  and drafts): tabs Colors | Palettes | Parts (leaving Palettes cancels an un-applied
  preview). ≥900 px: fixed-height two panes; <900 px: sticky stage (~34vh) + sticky tabs.
  The design route widens `.wrap` to 1680 px.

## Kit and startup (`kit-and-startup`)

- Migrations: one baseline, `drizzle/0000_red_apocalypse.sql` (the 14 earlier migrations
  were squashed on 2026-11-11). `runMigrations` (`db/index.ts`) first calls
  `upgradeLegacyChain` (`db/baseline-upgrade.ts`): a database at the complete old chain
  (14 journal rows, hashes in `LEGACY_CHAIN`) is brought to the baseline in one
  transaction (tables whose stored SQL differs from the baseline beyond whitespace are
  rebuilt, the journal is replaced by the baseline row, one log line names the rebuilt
  tables). A partial or unknown chain makes startup refuse and leaves the file untouched.
  New migrations are added after the baseline as usual. Old-chain fixtures for the tests:
  `db/fixtures/legacy-chain/`.
- Release upgrade guard: `src/lib/server/db/upgrade-from-release.test.ts` runs for every
  folder under `src/lib/server/db/fixtures/v*/` (frozen `schema.sql`, `data.sql` with
  invented rows in every data table, `meta.json` with the journal, row counts and spot
  checks). It applies the release's schema and data, runs `runMigrations`, and checks that
  no row, column or table was lost, the schema equals a fresh install's, a second run is a
  no-op, and the startup steps that need no network (`cleanupAuthDataAtStartup`,
  `seedTemplates`, `backfillBuildParts`, `repairTwinPlates`, `failStaleModelJobs`) leave
  the data alone. A second test fails when a released migration's file hash or journal
  entry changes. Released migrations are frozen: add a new one; each release adds a new
  fixture folder and never edits an old one.
- Startup order: migrations, then `cleanupAuthDataAtStartup` (`server/auth-cleanup.ts`:
  idempotent, one transaction, clears `session.ip_address` and unused account tokens, logs
  one counts-only line only when something changed), then seeding and the kit pack.

- Kit pack format, env (`KITPACK_DIR`, `KITPACK_URL`, `KITPACK_DOWNLOAD=off`) and how to
  build one: `docs/kit-pack.md`. Seed data contract: `src/lib/server/seed/README.md`.
- Startup: migrate → seed reconcile (`seed/run.ts`, upserts template data, never touches
  builds) → `backfillBuildParts` → `repairTwinPlates`.
- 3D model: STEP zip → `src/lib/server/models/` (forked worker bundled by
  `vite.worker.config.ts`, ~80 s / ~620 MB peak) → GLB with one node per slug in each
  STEP's own frame; placements (`template_part_placements`, column-major 4x4 + instances)
  applied at runtime. Hardware GLB built offline (`scripts/step-to-glb.mjs`).
- Kit admin (`/admin/templates/[id]`, site admins: first user or `ADMIN_EMAILS`): model
  upload and nudge editor.
- Template copies: switching a build back to the built-in kit leaves the unused copy.

- `templates/fork.ts`: kit copies (`forkTemplate`, `chooseBuildTemplate`, quota
  `kitCopiesPerWorkspace`, reuse of an unused copy at the limit), `canViewTemplate` /
  `assertTemplateViewable` (built-in, member of the owning workspace, site admin, or can see
  a design on that copy) on `model.glb`, `hardware.glb`, `kit-status`, `plate-layouts`,
  guide images. `templates/files.ts`: `kitCopyBytes`, `removeTemplateFiles`,
  `removeWorkspaceTemplateFiles`. `templates/kit-upload.ts` + `print-geometry-upload.ts`:
  kit uploads run public-mode rule (print-geometry import is site-admin only there), slot,
  over-quota, disk floor, stream, re-check.
- `models/jobs.ts`: `stepConversionsPerUser` (queued or running); `convert-core.ts`
  refuses zip entries over 512 MB or 1 GB in total. `guide.ts`: 300 pages per template,
  quota by size difference.
- `kitpacks/index.json` lists only pack 1.0.1 (1.0.0 dropped from the image, about 31 MiB);

## Release and deployment (`release-pwa`)

- Version: `src/lib/version.ts` (`APP_VERSION`, the `version` field of `package.json`, inlined
  at build time) is the one source, shown on `/about` and returned by `/api/health` as
  `{ ok: true, version }` (503 stays `{ ok: false }`).
- CI (`.github/workflows/docker.yml`, jobs `test`, `e2e`, `image`; top-level permissions
  are read-only, only `image` has `packages: write`): `test` always runs; `e2e` runs on
  `v*` tags, manual runs and, with the repository variable `CI_FULL=true`, on every push
  and pull request; `image` needs both and runs on pushes and manual runs with `publish`,
  never on pull requests. Tags published: a release tag `vX.Y.Z` gives `latest`, `X.Y.Z`,
  `X.Y`; a pre-release tag (with `-`) only its full version; the `edge` branch gives `edge`
  (pushes run on `main` and `edge`; `main` gives only `sha-<short>`); every
  build also `sha-<short>`. Without `CI_FULL` a push to `main` or `edge` publishes nothing. One run
  per ref; tag and manual runs are never cancelled. Issue forms live in
  `.github/ISSUE_TEMPLATE/` (bug, feature request, install or docs feedback, printer
  connection report; the app's Experimental note links to the last).

- Docs for operators: `README.md` holds only the intro, the Docker quick start and a guide
  list; everything else lives in `docs/guides/*.md` (unraid, reverse-proxy, sso,
  backup-and-upgrade, printers, environment, troubleshooting, phone-install, site-admin,
  slicer-export). A new env variable goes in `guides/environment.md`. Contributor docs:
  `CONTRIBUTING.md`, `SECURITY.md`, `.nvmrc` (22).
- Origins: see `CLAUDE.md` Stack (`scripts/proxy-origin.mjs`, `PUBLIC_URL`). The preload
  strips any inbound `x-tmt-forwarded-original` and sets it only when the client itself sent
  a forwarding header; `client-ip.ts` `shouldWarnUndeclaredProxy` reads only that marker for
  the one-time "reverse proxy" log hint (never for trust). `writeRateResponse` gets the host
  for its back link from `event.url.host`.
- Image: `ghcr.io/ayostepht/tmt-build-tracker` (`latest`, semver, `sha-<short>`), kit pack
  baked in, `VOLUME /data`, `HEALTHCHECK` on `/api/health`, `BODY_SIZE_LIMIT=1100M`.
  `three` and `pdfjs-dist` are devDependencies: browser-only, bundled by Vite into
  `build/client` (the pdf.js worker is a hashed static asset), so `npm prune --omit=dev`
  leaves them out of the image. Keep it that way: nothing on the server may import them.
- Unraid template `unraid/tmt-build-tracker.xml`; install guide in `README.md`.
- **PWA**: `static/manifest.webmanifest` (light colors; dark `theme-color` via media meta tags
  in `src/app.html`), icons in `static/icons/`, `static/offline.html` (self-contained, no app JS).
  `src/service-worker.ts` (SvelteKit registers it; imports `immutable`/`assets` from
  `$app/manifest`, `version` from `$app/env`) precaches those and answers only: cache-first
  precached files and `/_app/immutable/*`; versioned (`?v=`) kit GLBs via a runtime cache; a
  failed page navigation gets `/offline.html`. Rules live in `src/lib/client/sw-rules.ts`
  (never `/api/*`, `/invite`, `/reset-password`, non-GET, HTML documents). No `skipWaiting` until
  the page posts `SKIP_WAITING` (`src/lib/client/pwa.ts`, started from `+layout.svelte`, shows a
  toast with Reload). `scripts/response-defaults.mjs` sends `Cache-Control: no-cache` for the
  worker, manifest and offline page. Needs a secure context; plain-http LAN pages have no worker.
  The model runtime cache (`RUNTIME_CACHE` in `sw-rules.ts`) is bounded to 12 entries (oldest
  evicted) and is the only cache that can hold per-user content: `clearPrivateCaches()` in
  `pwa.ts` deletes it (never the shell precache) and sign-out / account deletion call it.
  Hardening: the shell rule is exact membership in the precache list (no `/_app/immutable/`
  prefix; paths with `%` or `..` never match) and stores only `basic` 200 responses;
  `putModel` swallows quota errors. The pdf.js worker (`isPrecacheExcluded`, 1.27 MB, kit guide
  import only) is not precached: it loads from the network on demand (guide import needs
  connectivity); precache is about 2.3 MB. A 401 from any `/api/` call in `client/api.ts`, and
  sign-out, call `clearPrivateCaches()` (`client/private-caches.ts`), which also posts on
  `BroadcastChannel('tmt-auth')`; `initPwa` listens so other tabs clear too.
  `src/service-worker.ts` is excluded from svelte-check (`tsconfig.json`); `npm run build`
  type-checks it.
- **Request pipeline** (`hooks.server.ts`): boot validation (`bootProblems`, exit 1) → body
  cap by route (`body-limits.ts`, default 1 MB) → `/api/auth/*` to Better Auth with a trusted
  client address (`client-ip.ts`: `ADDRESS_HEADER`/`XFF_DEPTH`; fails closed) → session →
  write rate → resolve with security headers (`security-headers.ts`; page CSP with nonces in
  `vite.config.ts`). `scripts/response-defaults.mjs` (preloaded by `proxy-origin.mjs`, must
  be copied into the image) adds default headers to static files and errors.
- **Limits by configuration**: `quotas()`, `maxThreeMfBytes()` (1024 MB, 256 in public
  mode), `minFreeDiskBytes()` / `diskHasRoom()`, `WRITE_RATE_*`; all validated at boot.
- CI: `npm audit --omit=dev --audit-level=high` in the test job; Dependabot (npm weekly,
  actions monthly).
